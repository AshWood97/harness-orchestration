# Focused checking and completion

Plan the requested behavior, implement the smallest change, then inspect the actual result against that requirement and directly affected callers. Reuse existing source observations and completed work. Checking is not an invitation to invent extra tests, builds, security audits, defensive code, compatibility layers, future abstractions or duplicate checking work. Useful parallel agents may execute distinct in-scope assignments; delegation itself is not extra work or a reason to ask for approval.

Assign one owner per concrete checking question: the host or a reviewer. An important change may justify independent checks of distinct functional questions, such as implementation behavior and its caller contract. Give those checkers the original requirements and relevant source before other conclusions. The host consolidates their grounds without repeating the inspections or deciding by majority vote. Task size or "more reliable" alone does not justify another checker.

A finding needs a concrete trigger, path/symbol, actual impact and source basis. Missing tests, hashes, future protections or process artifacts alone are not defects. A specific important behavior that cannot be settled from inspection may justify the smallest assigned test or reproduction within the user's task; explicit no-tests/read-only instructions still apply. Do not invent full-suite requirements or automatic test-author/tester chains.

Review remains read-only. A review-only request delivers findings and never authorizes repairs. During an implementation task, the writer fixes concrete in-scope defects; inspect only the repair and directly affected paths and reuse unchanged conclusions. Re-run a check only when its relevant input changed. Resolve a material disputed finding through finding_validator when necessary, not another whole review. Guardian answers a distinct unresolved result question only and is never a routine final gate.

Deliver when the requested behavior is complete and no concrete in-scope issue remains. Report actual changes, the focused inspection and real unresolved limitations concisely. Do not add a verification layer, test report, hash, log archive, sign-off document, diagnostic role or extra review for reassurance. For an action beyond the user's scope, stop that action, ask “我想加 X，因为 Y，是否允许？”, and wait.
