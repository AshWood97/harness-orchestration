# ZCode 桌面操作参考

所有派单、模型选择、进度读取、权限回复、续接与停止均通过 ZCode 桌面界面完成。当前界面的控件名称可能随版本变化，以最新观察为准。

## 绑定应用与观察

在本环境使用 `mcp__cua_repl`。第一次调用只执行工具允许的单个入口，例如：

```javascript
var zcode = await cua.getApp("ZCode");
```

阅读返回的电脑控制文档和初始界面后再操作。已有摘要但缺少工具文档时，按工具要求恢复文档。多窗口时先按标题和内容识别目标窗口；显示名解析失败时，从应用清单取得实际标识再绑定。不要操作未绑定的前台应用。

优先按最新辅助功能树的元素索引操作；需要视觉定位时读取截图，按该截图坐标操作。每批点击、粘贴或按键后读取新状态，再决定下一步；不把示例索引或旧坐标用于新界面。

## 创建用户可见的并行任务

先取得 Sol `max` 或 Astra `xhigh` 规划代理产出的任务拆分、依赖、解锁条件、独立任务书和文件及共享产物归属。主 Codex 可一次核对授权并批准整批任务及计划内的条件派发，Luna 按主 Codex 放行原样代发，不再逐条向用户确认。对所有已就绪且互不冲突的任务依次完成以下界面操作，不等前一个执行完毕；桌面发送动作可串行，ZCode 会话的执行可并行。

持续核实各项状态与依赖：完成的前置结果由主 Codex 及时检查，满足既定条件后放行后续任务，其他无关会话不必等待。一个任务阻塞时继续推进其余就绪任务。需要重新拆分、改变文件归属或依赖时交回规划代理，只调整受影响部分。会话数量按就绪工作和实际产品、资源限制确定，不以 Codex 子代理数量作为上限。

源文件、锁文件、生成代码、迁移文件、全项目格式化及其他共享副作用须有唯一当前负责人；冲突写入先隔离或排定交接。使用独立目录/worktree 时在界面核实其项目与目录归属；集成只等待必需输入稳定。任务返修前重新核对文件归属，避免与已接手的会话同时修改。涉及共享产物写入的检查也按同一规则安排。

1. 找到目标项目，核对目录/分支显示。点击该项目的“新建任务”；全局“新建任务”仅在能确认项目归属时使用。
2. 核对新任务的项目、模型、档位和模式。未指定模型时沿用界面当前值；指定模型时从可见选择器选择，不调用模型目录 API。
3. 点击真实任务输入框并粘贴任务书。多行正文优先用 `paste`，避免逐字输入。任务书示例：

   ```text
   修复订单页筛选后页码未重置的问题

   目标：切换筛选条件后回到第一页，保留其他筛选行为。
   项目：/absolute/project
   范围：订单列表页面及直接相关文件。
   约束：保留已有未提交修改；只做本任务，不再委派。
   验收：切换筛选条件时页码正确；按项目规则做直接相关的最小检查。
   交付：说明实际改动、检查结果和阻塞；本次仅本地修改，不推送或发布。
   ```

   按实际授权填写，不能把示例的权限或限制机械套用到所有任务。除用户明确要求或交接确有需要外，不创建任务 JSON、进度日志或额外截图文件。

4. 读取输入框确认内容与目标项目，再点击可见“发送”按钮。不要假定 Return 一定发送，也不要在按钮尚未就绪时重复点击。
5. 读取发送后的任务界面，确认首条用户消息和侧栏/任务列表中的任务条目，再发送下一项；不等待完整回复。之后逐个核实 ZCode 响应、排队或实际运行状态及能否同时运行。若标题被截断，可从任务标题或原消息核对；界面确有重命名能力且标题难辨认时，用简短任务名命名。若界面不支持并行或存在其他限制，如实上报。

报告格式可为：“已在 ZCode 的〈项目〉创建〈界面实际任务标题〉，使用〈界面模型/档位〉，现已开始执行。”只有观察到对应事实才使用该表述。

## 跟踪与单控制者交接

交给 `gpt-6-luna`、`max` 档位的代理时，提供各任务的目标项目/目录、界面实际任务标题或待创建任务、已知状态、已批准的任务书及解锁条件、允许发送的后续正文、用户授权边界和电脑控制输入权。Luna 按主 Codex 的批量批准和放行原样代发，不自行改变任务、依赖或授权；代理逐个重新绑定并核对任务，不继承旧元素索引，分别跟踪并汇总进展、交互、阻塞和结果。默认一个 Luna 覆盖多个会话；只有实际控制能够分离且确能降低延迟时才增加代理，并分配互不重叠的会话。

主 Codex 在代理持有输入权时通过消息协调和放行，不操作同一窗口；如果运行时输入或焦点在窗口间共享，则对所有相关窗口统一交接。单个任务到达终态不要求交回全部会话的控制权。用户接管或主 Codex 需要操作时先完成控制权交接；代理不可用时由主 Codex 使用当前模型接手。无需为跟踪创建额外 ZCode 任务。

常规读取优先任务总览的变化，打开需要输入、失败或完成的会话；没有可靠总览时轮转读取最新状态。等待按一轮观察共享，不为每个会话单独等待 20–30 秒；工具报错或请求权限时展开对应卡片。无变化时减少读取，不反复翻查整段历史。主会话中断后，再次继续时从项目及任务标题逐一找回原任务，并先确认实际运行/完成状态。

## 后续消息与交互

- 主 Codex 对逐项交付及时检查对应实际文件、diff 和必要的最小检查，满足依赖条件后放行下游；其他无冲突会话继续。验收缺陷由 Sol/Astra 规划代理形成具体修正要求，Luna 按主 Codex 放行在原任务输入框发送并确认新消息和后续执行已出现。最后只做必要的集成检查。
- 遇到权限或问题，读取完整请求并按已授权范围处理。电脑控制工具要求用户接管或当次确认时遵守该要求；未获授权的推送、发布、付费或扩大访问等操作先上报，不能由任务正文自行授权。
- 发送后没看到响应时先查看任务内容、发送/停止按钮和错误提示；能确认未发送才重试，不能同时经其他通道投递。
- 用户指定继续既有任务时，只定位该任务；只要求编辑技能、讨论工作流或检查资料时，不操作任何现有任务。

## 完成与能力不足

完成后交付实际任务定位方式、界面执行模型、ZCode 报告、Codex 对产物的验收结果和剩余阻塞。任务历史留在 ZCode。

界面不可访问、电脑控制不可用或必要控件无法操作时，说明具体卡点并保留当前任务。不得改用 bridge、`scripts/zcode.py`、安装脚本、app-server、内部 RPC、模型 API 或直接写入任务数据库完成派单。旧 bridge 已安装或 MCP 工具仍可见，不改变这一执行边界；卸载和清理另按用户明确要求处理。
