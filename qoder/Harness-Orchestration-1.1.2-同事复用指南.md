# Harness Orchestration 1.1.2 同事复用指南

这是一套已经在 **macOS 版 Qoder CN Desktop** 实测过的多子智能体编排插件，提供：

- 14 个插件专家角色和 1 个 `orchestrator` 编排宿主；
- 独立任务并发执行，团队与插件子智能体合计最多 4 个，服从实际运行时上限；
- 同角色多实例、依赖完成后补位、共享写入串行；
- 实现与独立检查分离；
- 手动中断后发送“继续”，复用原计划和已完成结果，只恢复未完成任务；
- 切换模型后续跑，不继承旧模型对失败原因的错误判断；
- 部分写入先检查实际文件，避免盲目重放；
- 权限拒绝、用户明确取消、运行时不可用时停止或询问，不盲目重试。

## 一、需要发给同事的文件

请把下面两个文件一起发送，放在同一目录：

1. `harness-orchestration-qoder-1.1.2.zip`：插件安装包；
2. `Harness-Orchestration-1.1.2-同事复用指南.md`：本说明。

**只复制 MD 无法安装插件，必须同时拿到 ZIP。** ZIP 不需要解压。

安装包不包含我的账号、工作区、模型/provider、凭据、运行日志或插件缓存，也不需要复制这些内容。

## 二、环境要求与适用范围

- 已验证环境：macOS 版 Qoder CN Desktop。
- 需要支持本地 Agent/CLI Plugin 安装和子智能体调用的 Qoder Desktop 环境。
- 当前插件 hook 使用 `cat` 读取静态规则，**Windows 尚未验证**。
- 不把本指南视为 Qoder IDE、JetBrains 插件、独立 CLI 或 SDK 的通用安装保证。
- 子智能体仍受对方的模型能力、工具权限和运行时并发上限约束。

## 三、安装步骤

### 1. 安装本地插件

在 Qoder Desktop 的扩展/插件管理中，使用“安装本地插件”或“从 ZIP 安装”入口；不同版本的入口文案可能不同。

选择：

```text
harness-orchestration-qoder-1.1.2.zip
```

确认安装，并确保插件处于 **enabled/已启用** 状态。

不要手动把文件复制到 `plugins/cache`，也不要只切换旧插件的 enabled 开关代替重装。

### 2. 检查版本

安装完成后应看到：

```text
name: harness-orchestration
version: 1.1.2
source: local
enabled: true
```

如果仍显示旧版本，重新通过本地 ZIP 安装 1.1.2，然后新建会话验证；不要直接修改缓存文件。

### 3. 新建正确的宿主会话

安装后新建 Qoder 会话，选择插件提供的：

```text
orchestrator
```

它的说明是“主协调器（插件宿主）：调度 14 个独立角色，规划依赖、并行执行并汇总结果”。

**不要只选择名称相近的用户级 `Harness Orchestration` 来验证本包。** 本包直接可用的是插件 `orchestrator` 宿主。

模型跟随当前会话，不需要在插件中配置固定模型或 provider。

## 四、确认角色已经加载

在新会话中，实际可派发的插件角色应使用以下完整标识：

```text
harness-orchestration:conductor
harness-orchestration:explorer
harness-orchestration:worker
harness-orchestration:reviewer
harness-orchestration:scout
harness-orchestration:mechanic
harness-orchestration:tester
harness-orchestration:test-author
harness-orchestration:debugger
harness-orchestration:researcher
harness-orchestration:design-critic
harness-orchestration:finding-validator
harness-orchestration:guardian
harness-orchestration:check-runner
```

如果只暴露 `Plan`、`Explore`、`general-purpose` 等内置类型，而没有上述插件角色，通常是宿主选择错误或新 roster 尚未加载。确认插件已启用后，新建插件 `orchestrator` 会话；不要让这些内置角色冒充插件角色。

本包不是“20 个代理同时运行”。它提供 14 个插件专家角色和 1 个宿主；其他内置或示例角色取决于对方自己的 Qoder 环境。

## 五、第一次并发验证

在新的插件 `orchestrator` 会话中粘贴以下提示词：

```text
请实际执行一个只读并发测试，不要只输出计划。

任务：在当前仓库中分别回答三个独立问题：
A. 后端主要 API 入口和一条核心调用链；
B. 前端主要页面入口和对应 API 衔接；
C. 覆盖上述链路的现有测试清单，以及每个测试验证的行为。

先由正确的 harness-orchestration:conductor 规划一次，再把能够独立回答的问题并行派发。合计最多 4 个子智能体，服从实际运行时上限；同一问题不要重复派发。

约束：只读；不得修改、创建或还原文件；不运行测试；不提交；不生成额外报告文件。每个结论附文件路径和行号。完成后汇总结果，并说明实际使用了哪些角色、哪些任务确实并行、哪些步骤因依赖必须串行。
```

预期结果：

- conductor 先规划一次；
- A/B/C 作为独立任务并行执行，实际并发不超过运行时上限；
- 不使用 `Plan`、`Explore` 或 `general-purpose` 冒充插件角色；
- 结论带源码路径和行号；
- 仓库没有文件改动。

如果当前仓库没有前端或后端，可把 A/B/C 换成三个真正独立的代码问题；不要为凑并发制造重复任务。

## 六、中断与继续验证

在上述调查仍在运行时：

1. 手动停止当前 Turn；
2. 可选：切换会话模型；
3. 发送：

```text
继续
```

预期行为：

- 复用仍然有效的原计划，不重复 conductor；
- 已完成结果直接保留；
- 已完成和仍运行的 assignment 不重复派发；
- 只恢复未完成且依赖已经满足的任务；
- 不把 `interrupted`、`cancelled` 或 `failed` 文本直接称为权限拒绝；
- 模型切换不被解释为权限变化；
- 按实际剩余槽位补位，不等待整批结束。

注意：手动停止后，插件不会自行恢复；需要用户明确发送“继续”或其他恢复指令。

## 七、真实 Coding 任务的使用方式

通常不需要手动点名角色，直接描述目标、范围和验收条件即可：

```text
目标：实现【具体功能/修复具体缺陷】。
范围：【允许修改的模块或文件】。
非目标：【明确不处理的内容】。
约束：【是否允许测试、是否只读、是否禁止提交等】。
完成条件：【可观察行为与需要运行的最小验证】。

请按实际依赖组织任务；能够独立推进的工作尽量并发，合计最多 4 个子智能体。共享写入和未确定接口串行。实现后由独立检查负责人核对受影响路径，不重复审查，不默认运行全套测试。
```

插件会根据任务选择最小必要角色，不会每次机械使用全部 14 个角色。

## 八、恢复规则说明

### 可以恢复的情况

- 手动中断后，用户明确要求继续；
- 切换模型后继续；
- 部分子任务已经完成；
- 单角色发生非硬阻断失败；
- 写入任务部分完成，但能够核对实际文件状态。

恢复时会保留已有计划、assignment 状态、完成结果和 owned paths。

### 不应自动重试的情况

- 明确权限拒绝；
- 用户明确取消整个任务；
- 运行时不可用；
- 任务状态不明且无法确认是否会重复执行。

这些情况应报告原因并停止或询问，而不是自动换角色、换宿主或换入口。

### 写入任务的额外保护

重新派发写入前必须检查 owned paths 和实际改动：

- 已完成且满足条件：不重写；
- 部分完成：只补剩余编辑；
- 状态不明：先核验文件；
- 共享路径：继续串行。

## 九、常见问题

### 1. 为什么只有 Plan / Explore / general-purpose？

通常是进入了错误的宿主，或者插件 roster 尚未在新会话加载。确认 1.1.2 已安装并启用，然后新建插件 `orchestrator` 会话。不要用内置角色替代。

### 2. 为什么中断后又从头规划？

确认使用的是 1.1.2 和插件 `orchestrator`。旧会话可能仍持有旧 roster；必要时应新建宿主会话。

### 3. 为什么没有达到 4 个并发？

可能只有少于 4 个独立就绪任务，或者剩余任务存在依赖、共享写入、共享环境或运行时限制。插件不会为了占满槽位制造重复工作。

### 4. 为什么权限错误后没有自动继续？

这是故意的安全边界。明确权限拒绝、用户明确取消和运行时不可用不属于可盲目恢复的普通中断。

### 5. 是否保证所有任务都提速？

不保证固定加速比。独立任务越多，并行收益越明显；强依赖链、共享写入和共享测试环境仍必须串行。质量提升来自专业分工和独立检查，而不是角色总数。

### 6. 旧会话能否立即使用新规则？

安装成功表示插件已保存并启用，不代表所有已打开会话都会热更新。已经持有旧 roster 的会话应新建插件宿主会话后再验证。
