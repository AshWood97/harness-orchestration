# Codex Qoder

主 Codex 保持当前模型，负责核对授权、协调派发与最终验收；Qoder CN 在桌面应用的真实任务中执行。只使用当前运行时的原生电脑控制工具操作 Qoder，保留用户可见的工作区任务、消息和历史。本技能不因查看、讨论或修改技能而启动 Qoder 任务；计划模式只规划，不派发执行任务。

## 规划与任务书

- 已有完整有效的计划与任务书时直接复用；简单明确任务由主 Codex 制定必要的简短任务书。需要新规划且有分工价值时，由独立规划代理制定计划：一般任务使用 `gpt-6.1-sol` / `max`，复杂或高风险任务使用 `gpt-6-astra` / `xhigh`。主 Codex 转交用户要求及必要上下文，检查任务书是否完整并符合授权；需要补充规划时交回规划代理。确需独立规划而指定规划者、模型或档位不可用，或用户禁止子代理时，说明限制并停止依赖该规划的派单，不以其他模型冒充规划者。
- 规划依赖、可并行工作、各任务的完成条件和文件或共享产物的唯一写入负责人。无冲突的已就绪任务可按 Qoder 实际能力并行；共同写入或接口未稳定时先确定归属或按依赖顺序执行。不为了凑任务数拆分工作，不新增无关检查。
- 每份任务书包含目标、实际工作区和执行目录、相关用户原始要求或准确摘录、必要背景、允许修改范围、限制、验收条件与已授权操作。跨应用任务还记录稳定 `task_id`、`attempt`、相关计划及交付版本、实际可见的会话标题或 ID、`effective_constraints`、资源和子代理预算、验收负责人及依赖版本；只有宿主实际提供时才记录原生 ID。摘要不得新增或改写用户要求；无法取得关键原始上下文时上报缺失，暂停依赖它的决定。相关上下文或任务失败本身不扩大授权。
- Qoder 不自动拥有 Codex 全部对话。在任务书传达必要约束；Qoder 的内部角色和并发以产品实际配置为准。用户未指定时保留界面当前模型、档位和权限，不改持久默认设置；明确指定时只通过界面选择并核对。只报告界面显示的模型信息，不猜测 provider 或用量。
- 由主 Codex 按整个任务分别分配外部会话、内部子代理、写入范围、共享资源、重试、时限和 UI 输入权；无法观察内部使用量时按分配上限保守预留。每个路径或共享资源同一时间只有一个写入负责人，无冲突范围可并行。预算和归属是协作约定，除非宿主实际提供控制，不宣称硬性限制。
- 需要时可由 `gpt-6-luna` / `max` 的 Codex 代理按主控放行原样代发定稿任务并跟踪；它不自行改写要求、扩大授权或再委派。可独立验收的交付可交 `gpt-6.1-terra` / `medium` 做范围内验证；主控结合实际结果最终验收，不重复已经完成的检查。若这些角色不可用，说明并由主控处理可处理的协调或验收，不冒充其结果。每个窗口同时只有一个控制者，焦点共享时跨窗口串行，先交接目标任务与输入权。

## 桌面派发与续接

1. 按当前电脑控制工具的首调用和操作文档绑定 Qoder CN 应用及正确窗口，使用最新界面状态定位控件，不猜测 API、索引或固定坐标。
2. 在界面核对指定工作区及其目录；创建任务时使用该工作区的可见新建任务入口。用户明确要求继续已有任务时定位指定历史任务，不把新目标塞进无关任务。目标、权限或状态不明确时先核实或报告限制。
3. 核对工作区、界面模型、权限和任务书，粘贴到真实输入框后再发送。读取新状态，确认用户消息和可定位的任务历史均已出现；只报告实际观察到的已发送、运行、排队或受阻状态。发送结果不明时先检查原任务，不能重复发送或另建任务替代。
4. 将进行中任务的纠错或补充交给原任务负责人，在原会话按界面实际支持发送；其他任务或超出原任务书分工的要求交回主控判断。确认是否已经接收，不重复派发；不得把消息出现等同于任务已执行或原子角色已实时收到。不能假定界面操作会停止命令、取消外部操作或自动续跑。
5. 区分已完成、等待必要结果和受阻；必要命令或子任务还在运行时不宣称整体完成。长命令是否允许接收消息由 Qoder 实际工具和界面决定；先确认状态，不承诺固定响应时限或强行中断。发生外部操作时先核实结果，避免盲目重投。
6. Qoder 返回 `completed`、`partial`、`blocked`、`failed` 或 `cancelled` 等实际执行状态及产物；需要裁定具体发现时才返回 verdict。主 Codex 检查固定交付版本及直接相关的最小必要验证；区分“Qoder 报告完成”和“Codex 已验收”。返修在原任务中按授权续接并关联原 `task_id` 和新 attempt。向用户交付工作区、实际历史标题、界面模型、已核实结果和具体限制；保留任务及历史，不自动归档或删除。

恢复时先核对原任务、已完成结果、仍运行工作、路径及共享资源归属。发送回执不明先查原会话，不能盲目重发；取消请求或主控失联不代表执行已停止，未确认旧执行者停止时不把相同写入范围交给新任务。独立且无冲突的工作可继续。

需要跨应用持久恢复的长任务，按[协调器与交接约定](https://github.com/AshWood97/harness-orchestration/blob/main/docs/orchestration-contract.md)从本地仓库调用可选状态库并登记实际桌面操作；该库不代替桌面控制。若库不可用，说明持久协调不可用，不声称已启用。

## 执行边界

仅用可见的 Qoder CN 桌面界面创建、续接、观察和处理本技能任务，不使用 CLI、隐藏 API、内部 RPC、数据库或会话文件代替界面，也不改动应用自动化配置。电脑控制不可用、界面缺少必要控件或无法确认目标时，保留现场并报告具体阻塞，不静默切换通道、模型或任务。对权限提示读取完整内容，遵守用户授权及当次工具规则；不自动扩大权限、推送、发布或发起付费生成。不要停止或接管其他用户任务。

[DeepSeek dsh-superagent](https://github.com/deepseek-ai/dsh-superagent-prototype) 是按需查阅的实验性设计参考，不是 Qoder 或本技能的运行依赖。
