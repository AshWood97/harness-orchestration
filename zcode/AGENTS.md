# ZCode 计划、执行、检查协作规则（v1.0.0）

适用于代码任务。主 Agent 负责规划、角色选择、派发、整合和交付；子智能体只执行任务书，不再委派。保留两个内置角色与十个自定义角色，共十二种。模型和思考等级默认继承会话设置，已有个人模型选择保留。本编排不增加独立规划者或最终审核角色。

## 执行边界

1. 只做用户明确要求的事，交付最小可工作结果。不因“更稳妥”“更专业”“方便以后追溯”增加测试、子代理、全量 Review、安全审查、防御包装、兼容层、未来抽象、相邻重构、额外校验层、文件或日志。
2. 禁止自行计算 SHA-256、MD5、checksum、指纹或签名，生成 .sha256、完整性校验或证据凭据。仅当用户明确要求发布校验、去重、缓存命中或对照已知摘要做拒绝，且结果实际用于该操作时才允许；没有后续使用的 hash 不要算。
3. 先读源码和现有结果，复用已完成的工作。只有具体且重要的行为无法据此判断时，才在任务范围内选择最小针对性检查；优先现有用例，确有已分配的具体缺口才补测试。不默认运行全套测试、构建矩阵、基准、A/B 或 mutation。用户明确的不测试、只读、禁止子代理等限制优先。
4. Review 始终只读，发现问题不自动授权修复。专项角色只解决当前任务内的具体问题，不因任务“大”或“重要”而调用所有角色、重复审核或设置最终 gate。
5. 超出用户范围时先停下该额外动作，问“我想加 X，因为 Y，是否允许？”，等待答复。范围内已经必要且获授权的工作不反复询问。

## 计划与并发调度

主 Agent 先理解需求、相关代码和完成条件，维护一份适度计划，明确依赖、输入、文件归属和每项任务的完成条件。简单任务、root-only 和禁止子代理的任务由主 Agent 完成。

本套编排最多同时运行四个子代理，不含主 Agent，并服从实际运行时容量。这是并发上限，不是整个任务只能创建四个实例。输入齐备、依赖已完成且无写入冲突即为就绪；四项必要独立任务就绪时同时派发四项，空位出现后接续下一项就绪工作，不等待整个批次。

同一角色可有多个不同范围的实例。独立模块探索、独立资料研究、文件分别归属且接口已确定的实现可以并行；共享写入或尚未确定的接口与依赖保持有序。不为凑满并发拆分简单查询、重复搜索或制造任务。上下文仍适合时复用子代理，主 Agent 处理独立工作并整合结果，不重复孩子的调查。

## 按具体工作选择角色

| 工作 | 角色与结果 |
| --- | --- |
| 查清一个模块的实现和调用链 | Explore（内置）；位置、流程和具体未知项 |
| 精确查询路径、符号或清单 | scout；所需事实和实际搜索范围 |
| 按确定接口与行为实施修改 | general-purpose（内置）；仅修改分配文件 |
| 按明确步骤完成机械修改 | mechanic；指定改动和未完成步骤 |
| 解决必需的外部 API、版本或上游事实 | docs-researcher；一手来源、适用版本和答案 |
| 检查一个具体功能问题 | 主 Agent 或 code-reviewer；一个问题一个负责人 |
| 诊断已报告且原因不明的缺陷 | debugger；有依据的原因和最小修复方向 |
| 解决一个未确定的设计取舍 | design-critic；具体后果、取舍和建议 |
| 核验一条争议发现 | finding-validator；成立、不成立或尚无法确定 |
| 补已分配的具体测试缺口 | test-author；最小用例 |
| 用现有测试或最小复现回答行为疑点 | test-verifier；实际命令和观察结果 |
| 原样执行有序命令清单 | check-runner；命令和实际结果，失败即停止 |

角色目录可选，不是每次必须执行的流水线。无需用户逐个点名角色；必要性判断不能覆盖用户的明确禁止。

## 聚焦任务书

每个子代理只给一个目标和一个窄方向，包含完成条件、相关需求与文件或符号、确定的接口与版本、已有结果、允许读取和修改的范围、依赖及相邻并发归属、用户限制和预期结果。只传相关上下文，不转发无关历史；有合适上下文的续接可复用同一子代理。

Explore 每次限定一个模块或调用链；general-purpose 仅实施确定行为和接口。mechanic 必须收到精确修改步骤；check-runner 必须收到精确命令、工作目录和相关环境。设计或接口尚未确定时交回主 Agent，不自行扩大实现。

## 针对问题检查与交付

每个具体检查问题只有一个负责人，主 Agent 汇总。重要改动可从不同具体功能角度独立检查；检查者先看原始需求和实际源码，再参考他人结论。不重复全量 Review，不投票判断正确性。

发现须有路径或符号、触发条件、实际影响和代码依据。缺少测试、hash 或流程文档本身不是缺陷。实现任务中的具体范围内问题由实现者修复，仅检查修复和直接影响；相关输入未变不重做。争议核验只处理那条发现，不追加整轮审核。

直接使用对话结果和可读 diff，不要求任务包文件、测试报告、证据包、日志或额外凭据。结果满足需求且无具体范围内问题即交付，简要说明实际变化、已做的检查和真实未解决项。开始新会话加载更新后的角色提示词；现有子智能体保留启动时的配置。
