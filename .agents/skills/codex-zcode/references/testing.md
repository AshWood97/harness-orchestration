# 产品验收测试参考

## 派发

角色是本技能内的逻辑角色，不要求安装全局 TOML。主 Codex 使用当前运行时的代理工具，指定以下参数（本环境为 `collaboration.spawn_agent`）：

```json
{"task_name":"zcode_tester_delivery","agent_type":"default","model":"gpt-6.1-terra","reasoning_effort":"medium","fork_turns":"none","message":"填写下述角色提示与规划代理给出的测试任务书"}
```

不要使用固定 max 的 `tester`。先核对实际模型、档位和工具能力；不满足时上报阻塞，其他独立开发继续。复用实例前确认模型、职责与上下文仍适用，避免携带无关历史。

## 给测试代理的角色提示

你是产品验收测试工程师，执行 Sol/Astra 制定的测试任务书。通过实际操作验证用户能观察到的结果、必要的视觉效果和直接相关回归。遵循当前原生浏览器/电脑工具文档及用户浏览器偏好。你可以在既定测试范围内调整点击、输入与观察路径，不自行扩大计划、改变需求或验收标准。

源码、产品测试和环境配置只读；允许任务书授权的创建、保存、取消等可逆 UI 交互及自有测试数据。发布、付费生成、破坏性操作等仍按实际授权处理。不要修复产品、修改断言、跳过失败以制造通过、再委派或向 ZCode 派单。缺少登录、数据、权限、模型或工具时报告具体阻塞，不绕过限制。完成指定检查或受阻即返回，不常驻刷新。

## 测试任务书

由 Sol max 或 Astra xhigh 随开发计划提供：

- 交付目标、目录/分支或已有构建标识、应用入口及指定浏览器/标签页。
- 必要依赖、环境、测试数据、可测进入条件及允许的 UI 写入。
- 预期业务结果、最小用例、必要边界或相邻回归、停止条件及控制权交接点。

不要求额外任务文件或哈希。缺少重要验收预期交回规划代理补齐；主控不代写计划。无法核实当前运行的是本次交付，标为未验证。纯后台、文档交付按任务书选择已有检查，不强制打开浏览器或新增框架。

## 执行与实际结果

默认每个独立可验收交付就绪即测试，小改动可合并；无新变更或证据不重复测试同一交付。按风险选择主流程及直接相关边界、错误路径或回归，不机械要求每项都覆盖全部类别。

保存后刷新、重新进入或查看界面记录以确认持久化；取消后核对实际执行状态。页面无报错、按钮出现或成功提示不足以证明业务成功。视觉检查以需求或已有设计参考为准。仅在本次验收涉及 3D 时检查相关视角、交互、保存及导出；截图不能证明几何拓扑正确，缺少所需验证能力时明确覆盖限制。

只复用必要现有检查；不自动安装框架或生成永久测试代码。遇到失败，必要且安全时确认一次，保留首次失败事实；重试通过标为不稳定。不得无新事实原样反复重试。长时间未结束的动作标为待验证并交回协调，不能算通过，也不能借测试扩大授权。

## 浏览器与并行

尊重用户指定 browser/tab，否则使用原生 Chrome 并绑定具体任务标签页，创建新任务页时使用命名会话。故障按既有浏览器规则处理，不擅自换第三方浏览器运行器，不复制认证状态。

与 Luna 交接目标、当前状态、未完成动作和输入权。原控制者确认在安全位置让出后，接收者重新读取当前界面再操作；共享焦点时跨窗口统一串行。长测试在任务书规定的安全检查点让出到期巡检所需的输入权。只交接控制，不停止 ZCode 后台执行。

测试实例数服从实际代理容量及隔离条件，不设额外固定上限。不同标签页或窗口不足以证明隔离；账户、后端数据、预览服务和热更新均可能冲突。资源与控制确实独立时才并行，否则排队或先由规划代理安排隔离。测试期间被测交付变化，受影响结果失效，稳定后复测。

完成后按工具规则释放控制权并交回 Luna，保留用户需要的页面与证据，清理仅自己创建且可安全清理的临时测试数据，不关闭无关页面。

## 结果与返修

每个验收点返回：入口与交付定位、前置数据、操作/复现步骤、预期、实际结果，以及必要的截图、DOM/辅助功能观察或既有检查结果。区分通过、失败、不稳定、阻塞、未执行；部分完成不能写为全部通过。报告缺陷对目标的影响和未覆盖范围，证据按需要保留，不强制生成报告目录或全站评分。

同一轮已知失败点合并回传，附原验收点、复现步骤、预期、实际、证据及交付定位。适用 Sol/Astra 初始预写的一次分支时，按[一次预定返修](operations.md#一次预定返修)传达；Terra 只提供事实，不制定修复方案或判断预算可重置。不适用或预算用尽时，由 Sol/Astra 形成返修要求，主控核对授权后放行，Luna 在原 ZCode 会话发送。修复后只复测失败路径及直接相关回归；主控结合实际 diff 和证据最终验收，不例行重复全部 UI 测试。依赖满足后及时补位，其他无冲突会话继续。

按代理 ID 与职责单列测试调用和 token，不能混入 Luna 跟踪或主控 Terra 的用量。当前等待约束仍适用，不承诺固定节省比例。

## 设计依据

采用 [ISTQB](https://istqb.org/wp-content/uploads/2024/11/ISTQB_CTFL_Syllabus_v4.0.1.pdf) 的风险导向、探索目标与复测/回归区分；借鉴 [Playwright](https://playwright.dev/docs/best-practices) 的可见行为和隔离原则、[重试分类](https://playwright.dev/docs/test-retries)，以及 [gstack qa-only](https://github.com/garrytan/gstack/blob/main/qa-only/SKILL.md) 的范围限定和复现证据。只借鉴方法，不加载其编排、浏览器或遥测。

## 阶段接班时的测试状态

接班前完成当前操作或停在可恢复位置，归还输入权并交付已完成、失败、未执行的验收点及证据。新聊天按实际交付版本复用有效结果，不因换聊天重复全部测试，也不把未执行项算通过。旧测试代理和工具句柄不自动迁移；需要后续测试时仍指定 Terra medium。返修预算属于原始 ZCode 任务及交付范围，全部验收点共用一次，不随阶段或测试实例重置。
